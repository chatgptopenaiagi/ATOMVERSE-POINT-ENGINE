# Operational AI awareness

The local model is discovered and measured, not assumed to be “Qwen 30B.” The verified installation reports qwen3.8:27b, qwen35 architecture, 27.3B parameters and Q4_K_M GGUF, served by the existing Ollama/llama.cpp infrastructure. Source and packaged tests use a private loopback server and stop only the test-owned processes. No weights are downloaded or published.

Qwen receives a bounded current-state summary and the most recent committed event summaries for the active session. Hardware values are included only when the operator enabled observation. The summary identifies simulated state, recorded information and observed telemetry separately. It does not enumerate processes, credentials, files or unrelated applications.

Model output is a structured proposal. Absolute destinations and relative displacements have explicit, distinct instructions. Movement, appearance, interaction and oscillator commands pass the same strict validator as direct controls. Historical queries accept only a bounded count, not SQL. Explanations are labeled AI_INTERPRETATION and can cite only supplied evidence references. Read-only answers never become kernel commands. Any executable proposal remains visible for review before the operator applies it.

The model runs in an independent worker with bounded input, response size, context and timeout. The renderer and simulation continue while it runs. The engine works without a model server. A successful bounded command suite establishes only that suite's behavior; it does not establish unrestricted language correctness, subjective consciousness, or scientific truth.
