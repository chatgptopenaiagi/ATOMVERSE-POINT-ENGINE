# Changelog

## 0.3.0-alpha.1 — One kernel, multiple distributions

The core is now an installable pure-Python wheel with a dependency-free headless CLI and public API. Qt, ODBC and telemetry move into optional extras. Windows has a standalone EXE and a portable folder build. Both retain the original kernel, native views, history and optional reviewed Qwen workflow. Missing optional ODBC bindings are reported without an unhandled worker exception.

A native Android control surface embeds the same Python kernel through Chaquopy. Publication is gated on installing and executing the signed ARM64 APK, lifecycle/history tests and numerical comparison. Mission 003 evidence records the final status; build success alone is insufficient. Previous releases and 32 existing local histories are preserved.

## 0.2.0-alpha.1 — Two worlds, one entity

The original point kernel remains authoritative. The entity can now evolve with its visualization closed, expose a dimensionless oscillator and bounded information state, and support create/delete/restore operations without deleting historical evidence. Sphere, wave, spiral, signal and data views observe the same state. Optional hardware telemetry maps through an explicit bounded formula that can be disabled immediately.

SQL recovery now binds ODBC batch payloads explicitly, repairing the reproduced `length 924 buffer 510` failure. A real server test recovers 1,003 records and verifies idempotent retry. Dedicated database creation remains blocked by SQL permissions; local history is verified and permanent-storage performance is not claimed.

The simulation uses measured high-resolution waits. Cached sphere geometry reduces CPU drawing overhead. Action-specific AI JSON schemas, explicit absolute/relative/appearance/trajectory/collision examples and compact awareness summaries repair the failures found by the expanded Qwen suite. Eight GPU layers are selected for the varied Mission 002 workload, with CPU-only operation still available.

The original candidate is preserved. Old recorded states remain readable, and the final release has automated numerical/storage/schema tests, real native GUI checks, headless executable checks, actual Qwen inference and source-backed evidence. Mission classification remains PARTIAL until the dedicated SQL deployment is completed.

## 0.1.0-alpha.1 — The first atomic point

Preserved local foundation: one binary64 XYZ entity, native GPU-rendered sphere, line/circle/spiral/helix/custom/polyline trajectories, wall rules, fixed simulation time, local durable journal, SQL replica, reviewed local-model proposals and 47 baseline tests. This candidate was preserved before Mission 002 extension; it was not previously published as a separate GitHub release.
